# tasks/

Machine-written verification reports from sweep scripts, mostly the x402 paid-endpoint rails plus the asset-grading probes. Nothing here is hand-authored: every file is regenerated by rerunning the script that produced it. These are audit evidence, not a product surface, and the server does not read this directory at runtime.

## Contents

| Directory | Files | Written by |
|---|---|---|
| [x402-bazaar/](x402-bazaar/) | `settle-sweep-report.json` | [scripts/x402-bazaar-settle-sweep.mjs](../scripts/x402-bazaar-settle-sweep.mjs): pays each bazaar endpoint for real and records settlement results. |
| [x402-ring/](x402-ring/) | `COVERAGE.md`, `coverage-report.json` | [scripts/x402-ring-coverage-sweep.js](../scripts/x402-ring-coverage-sweep.js): verifies every ring endpoint (402 challenge, Solana accept, settle signature, response, business effect) and writes the human table plus the machine record. |
| [x402-ring/](x402-ring/) | `datapoint-seed-report.json` | [scripts/x402-seed-datapoints.mjs](../scripts/x402-seed-datapoints.mjs): seeds datapoints and records the outcome. |
| [sim-readiness/](sim-readiness/) | `probe-<date>.json` | [scripts/sim-readiness-probe.mjs](../scripts/sim-readiness-probe.mjs): pulls real GLBs off the live site and grades each one for simulation readiness (watertightness, metric scale, mass and inertia, convex proxy), recording the per-asset report and the pass rate per source. |

## Adding a file

A new sweep or verification script that produces a durable report should write into `tasks/<campaign>/`, one directory per campaign, and name the file after what it records (`<thing>-report.json`, plus a Markdown table if humans need to read it). Prompt documents and work orders do not belong here; those live in [../prompts/](../prompts/).
