01 / how a memecoin earns a card

Nine rules, all objective,
re-run every refresh.

Stock Tokens come from the hoodchain registry and cross-check against Robinhood's own contracts registry. Memecoins have no registry, so a full event-history scan of the NOXA (TokenLaunched) and The Odyssey (PoolMigrated) launchpads is filtered through nine published criteria against live liquidity, holder and honeypot-simulation checks.

02 / reading a Stock Token correctly

Two rules integrators
must not skip.

ERC-8056 · uiMultiplier
A true position is raw balance × uiMultiplier() (1e18-scaled). Every stock entry sets extensions.supportsUiMultiplier: true. Never display a raw balance as the position.
feed prices are adjusted
A Chainlink answer for a Stock Token is already multiplier-adjusted — never re-apply uiMultiplier to it.
eligibility
Stock Tokens are tokenized debt securities and may not be offered, sold, or delivered to US persons (also limited in Canada, UK, Switzerland). Every stock entry carries extensions.eligibility: "not-for-us-persons" so buy flows can gate on it. Displaying the data is unrestricted.
verification
On every refresh: on-chain symbol/name/decimals/uiMultiplier, a shared EIP-1967 beacon check, a cross-check against Robinhood's published contracts registry, and Chainlink feed answers.
03 / value-add per token

Everything extra lives
in extensions.

assetClass
One of stock-token, memecoin, stablecoin, wrapped-native.
chainlinkFeed (+ decimals)
The aggregator address and its answer decimals, for every priced token. null when no feed exists.
supportsUiMultiplier
ERC-8056 flag — true only for Stock Tokens.
launchpad · uniswapV3Pool · launchBlock
For memecoins: the launchpad (noxa / odyssey), the V3 pool and fee tier, and the block it launched at.
eligibility
The not-for-us-persons marker on Stock Tokens.
04 / use it

One URL, or one
npm install.

Paste the stable URL into any Uniswap-compatible interface, wallet, or aggregator under "Manage token lists". It always serves the current list; every address is re-verified on each refresh, and a refresh that changes nothing produces a byte-identical file, so diffs are always meaningful.
