ERC-8056

When a tokenized stock splits or reinvests a dividend, its raw ERC-20 balances never change. The issuer updates one number, uiMultiplier(), and every correct integration scales its display and valuation by it, exactly once. This document is that rule, spelled out clause by clause, with the deployed-reality caveats in the margins. Engage any note to expand it in place; follow a cross-reference and the spec draws the line for you.

1.

Abstract

ERC-8056 (“Scaled UI Amount”) defines uiMultiplier(): an 18-decimal fixed-point factor a token issuer maintains so that a token's displayed and valued amounts track corporate actions while its raw on-chain balances stay immutable. It is the standard behind Robinhood Chain Stock Tokens.

This package is both the reference implementation and, on this page, the living specification: the math is bit-for-bit the on-chain math, and the price types make the wrong valuation branch a compile error. See §4 (positions) and §5 (valuation) for the two rules everything reduces to.

// margin
A raw balance is what the ledger stores; the UI amount is what a human should see. balanceOfUI = balanceOf × uiMultiplier ÷ 1e18, floored. The multiplier is the only moving part, so a split becomes a single storage write instead of a rebase across every holder.
2.

Motivation

Every naive integration gets tokenized equities wrong in one of exactly two ways. This standard, and this package, make both mistakes hard.

  • Showing raw balances as shares understates positions: after a split or reinvested dividend the true share-equivalent has diverged from the raw ERC-20 number. Fixed by §4.
  • Re-applying the multiplier to an already-adjusted price feed double-counts the corporate action. Fixed by §5 and the trap in §6.

The remedy is a discipline, not a library call: apply the multiplier exactly once, and know which side of the trade already applied it.

// margin
A rebasing token rewrites every balance on every corporate action, expensive, and it breaks any contract that cached a balance. Scaled UI Amount keeps balances immutable and moves the adjustment to read time, so integrators opt in by reading uiMultiplier() rather than being forced to track rebases.
3.

The multiplier

uiMultiplier() returns underlying shares per token as an 18-decimal fixed-point number. MULTIPLIER_ONE is 10n ** 18n. A token that has never had a corporate action reads exactly one; a split or dividend moves it.

Read it with readUiMultiplier(client, token), which throws Erc8056NotImplementedError for a plain ERC-20 rather than returning a misleading zero. For scheduled changes, readMultiplierState returns the current value and a pending one.

// margin · live
Token WEEK at 0xc93a8c440CEa26D7445dF01729f193b27965099f. On 2026-07-15 its multiplier read 2006182524271844660n, i.e. 1 raw WEEK token = 2.0062 shares. Read it yourself; the value is pinned by this package's live test suite, not folklore.
After a scheduled change activates, newUIMultiplier() and effectiveAt() retain the last applied values. “Pending” means a future effectiveAt and a differing value, exactly what readMultiplierState encodes, so you never mistake history for a queued action.
4.

Rule 1 · positions

Raw balances understate holdings. The true share-equivalent is:

// bit-for-bit the on-chain balanceOfUI() math trueBalance({ raw, multiplier }) = raw × multiplier ÷ 1e18 // floored

trueBalance floors exactly as the chain does, so your number equals balanceOfUI to the wei. This is the number to show a user as “shares held”, never the raw ERC-20 balance. It depends only on §3 (the multiplier).

// margin
toUiAmount / fromUiAmount perform the spec conversion math in JS, because the on-chain conversion extension (toUIAmount/fromUIAmount) is not deployed, calls revert. See §7.
5.

Rule 2 · valuation

To value a position you must declare what kind of price you hold. A bare number does not compile; the only way to make a StockPrice is a branded constructor:

// feed price (USD per TOKEN): multiplier NOT re-applied trueValue({ raw, multiplier, price: adjustedPrice(100.62) }) // share quote (USD per SHARE): multiplier applied once trueValue({ raw, multiplier, price: rawPrice(100.53) })

The multiplier is applied by trueValue exactly zero or one times, decided by the price's brand. Choosing the wrong brand is the trap in §6, and here it is a type error, not a silent loss.

// margin · the table
adjustedPrice(usd), a Chainlink feed answer on Robinhood Chain. The multiplier is already inside the price; trueValue applies it never.

rawPrice(usd), an off-chain exchange or broker share quote. The multiplier is applied exactly once. Passing a plain number is a deliberate compile error.
6.

The one trap, spelled out

On Robinhood Chain, Chainlink Stock Token feed answers are already multiplier-adjusted: the answer is the price of one TOKEN, not one underlying share. Robinhood's docs state it, and the market confirms it. So you scale the balance (§4), and you take the feed price as-is (§5).

Get this backwards and every position off a live feed is wrong by the multiplier, here, off by roughly 2× on WEEK.

// margin · evidence
At block 10,745,112 the Uniswap v3 SGOV/USDG pool priced the token at $100.6075; the Chainlink feed answered $100.6215; the unadjusted share price was $100.5252. The pool and the feed agree on the token; only the share price differs, proof the feed already carries the multiplier.
7.

Deployed reality vs the draft

Facts about Robinhood's deployed Stock implementation (0xb354…5aE2, verified source) that the spec draft alone will not tell you. This package encodes the deployed flavor, not the draft's.

  • The optional transfer event is TransferWithScaledUI, not the draft's TransferWithUIAmount. Both ABIs ship; indexers need the deployed topic.
  • The conversion extension is not implemented; calls revert. This package computes conversions locally (§4).
  • Issuer updates go through updateMultiplier(uint256) and updateMultiplier(uint256,uint256).
// margin
TransferWithScaledUI hashes to topic 0x37e7f0db…3802. Subscribe to that, not to the draft's TransferWithUIAmount, or you will index nothing on the live chain.
8.

API surface

Nine reads and constructors, one ABI. Detection never throws; a plain ERC-20 resolves cleanly to false.

  • readUiMultiplier · readMultiplierState · watchMultiplier, read and follow the factor and its UIMultiplierUpdated events (§3).
  • trueBalance · trueValue · adjustedPrice · rawPrice, the two rules and their branded prices (§4, §5).
  • supportsErc8056 · detectErc8056, ERC-165 first, direct probe fallback, per-extension report.
  • erc8056Abi · INTERFACE_IDS · MULTIPLIER_ONE, ABI fragments and constants (§9).
// margin · quickstart
import { readUiMultiplier } from 'erc8056' const m = await readUiMultiplier( client, WEEK) // 2006182524271844660n
9.

Interface IDs

Four ERC-165 interface identifiers, taken from the spec, re-derived from selector XOR, and confirmed by live supportsInterface reads against real Stock Tokens.

core 0xa60bf13d metadata 0x4bd27648 events 0x57854fc3 conversion 0xd890fd71 // declared, not deployed (§7)
// margin
Trusting a draft's printed ID is how indexers ship dead detection. Every ID here is XORed from its own selectors and checked against a live supportsInterface call, so the constant and the chain agree before you depend on it.
10.

Reference implementation

contracts/src/IERC8056.sol declares all four spec interfaces plus an ERC8056InterfaceIds constants library. ERC8056Consumer.sol is the commented pattern for consuming these tokens from another contract, detection, true balances, and both valuation branches, with the multiplier deliberately absent from the adjusted-feed branch.

Fork tests run against live mainnet Stock Tokens, read-only, no keys, no funds:

# asserts, against the chain itself: # totalSupplyUI == totalSupply * uiMultiplier / 1e18 forge test --fork-url https://rpc.mainnet.chain.robinhood.com
// margin
Against AAPL / SGOV / WEEK it asserts: mandatory ERC-165 answers, live multiplier values, totalSupplyUI == totalSupply × uiMultiplier ÷ 1e18 bit-for-bit, balanceOfUI agreement on a real top holder, the absence of the conversion extension, and that valuation never re-applies the multiplier.
