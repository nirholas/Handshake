The receipt
prints itself.

A plain USDG transfer carries no invoice field. hood-pay attributes every payment two honest ways. Type an amount and ring it up: the dust fingerprint, the real payment link, and the router reference all print below. Nothing is sent anywhere.

terminalidle · press ring up
payTo A checksummed Robinhood Chain address. viem's getAddress rejects a mistyped one before a link is ever built.
the fragment The payment request lives after the URL's # — the browser never sends it to a server, so a hosted link page leaks nothing.
// the memo problem
USDG has no memo.
Two ways to fix that.

USDG is a plain ERC-20; its transfer can't say which invoice it settles. So a payment is fingerprinted either on-chain or in the amount itself — never guessed.

on-chain
Router mode
The buyer pays through the stateless, non-custodial HoodPayRouter. Its pay(token, payTo, amount, ref) pulls funds straight to the merchant via transferFrom and emits PaymentReceived(reference, payer, payTo, token, amount) — exact attribution regardless of the amount. No owner, no pause, no balance held.
zero contracts
Direct mode
The invoice amount itself is fingerprinted in USDG's unused low decimal digits: 25.00 becomes 25.00 42 00, its last four digits a per-invoice dust marker. A bare transfer settles it, and it works with any ERC-20. directCollisionProbability(k) bounds the odds for k concurrent invoices.
// three pieces, each stands alone
Core, widget,
and verify.
Core · hood-pay
Networks, the payment-request type and URL-fragment link codec, the reference/dust attribution scheme, and unsigned-tx builders for direct transfers and router-mode payments. No wallet, no server.
Widget · /widget
An embeddable checkout that mounts on any [data-hoodpay] element or via mountCheckout() — no bundler required. Wallet discovery and chain add/switch run through hood-connect (EIP-6963 / EIP-3085), never re-implemented here.
Verify · /verify
Node-only: a reorg-safe on-chain payment watcher, an idempotent SQLite ledger, HMAC-signed webhooks, and refund helpers for the merchant side.
peer dep viem ≥ 2.55. hood-connect and hoodchain install automatically.
// merchant side · reorg-safe
Settled means
settled.

The watcher only counts a payment once it is buried deep enough that a reorg can't take it back — then it fires a signed webhook and never fires twice.

01
Scan at depthawaitPayment / checkPayment only read blocks at depth ≥ confirmations below the head (default 30, ~3s of Robinhood Chain's ~100ms blocks).
02
Re-fetch every block hashEach candidate log's block hash is re-fetched by number and compared. A block reorged out after the scan but before the re-check is dropped.
03
Idempotent ledgerAn SQLite ledger reserves dust fingerprints, enforces monotonic status transitions, and records transfers replay-safe. A confirmed result is stable under any reorg shallower than confirmations.
04
Signed webhookDelivery is HMAC-SHA256 signed and constant-time verified; a stale timestamp is rejected (5-minute default). The ledger stays the source of truth for amounts.
// there are no keys here
Non-custodial,
always.
Buyer keys
The widget only builds unsigned approve / transfer / pay calls for the buyer's own EIP-6963 wallet to sign. hood-pay never holds them.
Merchant keys
Refunds build unsigned calls for the merchant's own signer (sendRefund or any viem WalletClient). buildRefundTx, refundOverageTx, refundReceivedTx.
Addresses
Every address (payTo, token, router) is validated against its EIP-55 checksum. A mixed-case address with one wrong character throws before a link exists.
Not a Stock Token
hood-pay settles in USDG or any ERC-20 a merchant configures — it never touches Robinhood Chain's tokenized-equity Stock Tokens.
// install
Ship a checkout
in one script tag.

The widget auto-mounts every element with data-hoodpay on load. No build step, no server, no keys.

<!-- drop-in checkout, auto-mounts -->
<div data-hoodpay
     data-pay-to="0x4022de2D…0564f402"
     data-amount="25.00"
     data-memo="Invoice 7"></div>
<script src="https://unpkg.com/hood-pay/widget.js"></script>
# or from a bundler / Node
npm install hood-pay   # viem >= 2.55 peer

# make a payment link from the CLI
npx hood-pay link --to 0x4022… --amount 25 --memo "Invoice 7"

# watch + verify a payment, no code
npx hood-pay verify --to 0x4022… --amount 25.0042
