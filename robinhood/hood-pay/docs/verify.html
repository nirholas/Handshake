Verify + webhooks

The widget builds unsigned transactions; it never decides whether a payment happened. Your server does, by reading the chain with hood-pay/verify (Node-only). Install with npm install hood-pay.

Await a payment

awaitPayment polls the chain until the invoice settles, the timeout elapses, or an AbortSignal fires. It never rejects on settlement grounds - the returned result carries a terminal status you handle explicitly.

import { networkInfo } from 'hood-pay'
import { awaitPayment, createReader } from 'hood-pay/verify'
import { parseUnits } from 'viem'

const info = networkInfo('mainnet')
const reader = createReader('mainnet')

const result = await awaitPayment(
  {
    token: info.usdg.address,
    payTo: '0x4022de2D36C334E73C7a108805Cea11C0564f402',
    expectedRaw: parseUnits('25.00', info.usdg.decimals)
  },
  {
    reader,
    fromBlock: await reader.getBlockNumber(),
    confirmations: 30,        // reorg depth before a log counts
    timeoutMs: 600_000,
    onState: (r) => console.log(r.status, r.receivedRaw)
  }
)

Signed webhooks

Deliveries carry a hood-pay-signature: t=<unix>,v1=<hmac-sha256> header over "<t>.<body>". Verify it constant-time and reject stale timestamps. The payload is a hint - the ledger and watcher remain the source of truth for amounts.

import { verifyWebhookSignature, SIGNATURE_HEADER } from 'hood-pay/verify'

app.post('/hooks/hood-pay', (req, res) => {
  const ok = verifyWebhookSignature(
    process.env.HOOD_PAY_WEBHOOK_SECRET,
    req.rawBody,                 // the exact bytes received
    req.get(SIGNATURE_HEADER)
  )
  if (!ok) return res.sendStatus(400)
  // event.payment.status is authoritative because the emitter read it on-chain
  res.sendStatus(200)
})

Idempotent ledger

The SQLite ledger (node:sqlite, no native deps) keys transfers on (txHash, logIndex), so replaying a webhook or re-running the watcher can never double-credit. Direct-mode invoices atomically reserve a unique fingerprint amount, so two invoices at the same price can never collide.

import { createLedger } from 'hood-pay/verify'

const ledger = await createLedger('./shop.sqlite')
const invoice = ledger.createDirectInvoice({
  network: 'mainnet',
  payTo: '0x4022de2D36C334E73C7a108805Cea11C0564f402',
  token: info.usdg.address,
  baseRaw: parseUnits('25.00', 6),   // low 4 decimals free for the fingerprint
  memo: 'Order 1042'
})
// invoice.expectedRaw carries a unique dust fingerprint the verifier matches

Refunds

hood-pay never holds the merchant's keys. Refund helpers build the unsigned ERC-20 transfer; sendRefund drives a viem wallet client the merchant supplies (key from ROBINHOOD_CHAIN_PRIVATE_KEY, never from this library).

  • Overpaid - refundOverageTx(token, result) returns the overage back to the payer.
  • Underpaid / abandoned - refundReceivedTx(token, result) returns everything received.
  • Full refund - buildRefundTx(token, payer, expectedRaw) for any signer.
