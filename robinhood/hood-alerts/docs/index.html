01 / WHAT IT DETECTS

Seven detectors,
one shared engine.

Every event is deduped per fingerprint, routed through a premium / quiet-hours / digest gate, and rendered as a platform-native card with links back to the explorer and three.ws/markets/robinhood.

02 / THREE TRANSPORTS · one router

Telegram, Discord,
and X, off one gate.

Both bots share one command router, so the UX is identical modulo native slash-command versus /command arg syntax. Leave a token unset and that transport simply stays dark; the engine and console transport keep running regardless.

03 / FREE VS PREMIUM · x402 on-chain

The arb signals
are paid.
The rest is free.

The premium/discount arbitrage feed and the liquidity-pull rug warning are the premium detectors. Everything else runs free, forever. Premium is paid on Robinhood Chain itself via x402: sign a USDG authorization, and the entitlement activates only once the transfer settles on-chain. A signature alone buys nothing.

04 / SELF-HOST

Runs with zero
config first.

With no environment variables the engine still runs: detectors connect to the public Robinhood Chain RPC, alerts print as structured JSON on the console transport, and /healthz comes up on :8080. That is the smoke-test mode. Add a Telegram and/or Discord token to go live on those platforms.

The console transport is not a fallback, it's the proof: a fresh self-host confirms the pipeline works on real chain events before you touch a bot token.

05 / GET IT

Point it at the chain.
Flip the switches.

One long-running process holds the engine, the HTTP server, and both bots. Run it as a warm service with a volume at /data so subscriptions, entitlements, and the delivery log survive restarts. SIGTERM flushes pending digests before exit.
