Integration guide

Three ways in, smallest first: the framework-free core, the React kit, and the wagmi config. All three share the same guarantees: chain parameters derived from viem's official definitions, typed errors for every wallet rejection, and real reads against the public RPC.

Vanilla JS (framework-free core)

No React, no wagmi, ~5 KB of logic on top of viem. This is what powers the live button on the overview page.

import {
  discoverWallets,   // EIP-6963 multi-wallet discovery (+ legacy fallback)
  ensureChain,       // connect -> add 4663 if missing -> switch -> verify
  checkBootstrap,    // live ETH + USDG balances, funding options when empty
  addNetwork,        // bare EIP-3085 add, no connection required
} from 'hood-connect'

const wallets = await discoverWallets()
if (wallets.length === 0) {
  // Designed empty state: render install links, not a dead button.
}

const { address, chainId } = await ensureChain(wallets[0].provider, {
  network: 'mainnet',           // or 'testnet' (chain 46630)
  onState: (state) => {
    // 'connecting' | 'switching' | 'adding' | 'connected' | 'error'
    updateButtonLabel(state.status)
  },
})

const status = await checkBootstrap(address)
if (!status.funded) {
  // status.fundingOptions: bridge funnel + Robinhood-app withdrawal path
}

Error handling

Every rejection path is a typed error; no string matching on wallet messages.

import {
  ConnectionRejectedError,   // user rejected eth_requestAccounts (4001)
  ChainAddRejectedError,     // user or wallet refused wallet_addEthereumChain
  ChainSwitchRejectedError,  // refusal, or wallet stayed on the wrong chain
  NoProviderError,
} from 'hood-connect'

try {
  await ensureChain(provider)
} catch (error) {
  if (error instanceof ConnectionRejectedError) showToast('Connection cancelled.')
  else if (error instanceof ChainAddRejectedError && error.rejectedByUser)
    showToast('You declined adding Robinhood Chain.')
  else showToast(error.message)
}

React

One component for the whole flow, or headless hooks for a custom UI. React is an optional peer dependency; installing the core alone never pulls it in.

import { HoodConnectButton, FundWallet } from 'hood-connect/react'

export function Header() {
  return (
    <HoodConnectButton
      network="mainnet"
      showBalances                 // live ETH + USDG in the connected pill
      onConnected={({ address }) => analytics.identify(address)}
      onFund={() => openFundingModal()}   // shown when the wallet is empty
    />
  )
}

export function FundingModal() {
  // Live LI.FI/Relay bridge quotes + execution, plus the Robinhood-app path.
  return <FundWallet onFunded={() => closeModal()} />
}

Headless hooks

import { useHoodAccount, useEnsureChain, useWallets } from 'hood-connect/react'

function CustomConnect() {
  const { wallets, ready } = useWallets()
  const account = useHoodAccount()
  // account.status: 'disconnected' | 'connecting' | 'switching' |
  //                 'adding' | 'connected' | 'error'
  // account.bootstrap: live balances + funding options
  // account.wrongChain: connected but the user switched away

  if (!ready) return <Skeleton />
  if (account.status === 'connected') return <Pill address={account.address} />
  return <button onClick={() => account.connect(wallets[0])}>Connect</button>
}
Styling. Components inject a namespaced skin (all rules under .hc-, themable via CSS custom properties like --hc-accent). Pass unstyled to skip injection and bring your own CSS.

wagmi

Already on wagmi v2? One import wires Robinhood Chain into your existing provider tree. EIP-6963 connector discovery stays on.

import { WagmiProvider } from 'wagmi'
import { QueryClient, QueryClientProvider } from '@tanstack/react-query'
import { hoodWagmiConfig } from 'hood-connect/wagmi'

const config = hoodWagmiConfig({
  includeTestnet: true,                       // optional chain 46630
  rpcUrl: import.meta.env.VITE_ALCHEMY_RPC,   // optional paid RPC
})
const queryClient = new QueryClient()

export function App({ children }) {
  return (
    <WagmiProvider config={config}>
      <QueryClientProvider client={queryClient}>{children}</QueryClientProvider>
    </WagmiProvider>
  )
}

The core utilities still work alongside wagmi; checkBootstrap and the funding funnel take any address, and toAddChainParams accepts any viem chain.
