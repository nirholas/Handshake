Safety model

Four gates before anything is signed.

The data server holds no key and can only read. Everything on this page is about the second binary, hood-mcp-trading, which does hold a key. A language model choosing tool calls is not a trust boundary, so the guards are in the server, ahead of the signer, and each one is independent of the others.

Two servers, never one. The trading tools are not registered on the data server and cannot be reached from it. Installing hood-mcp from Smithery, Claude Code, or npm gives a client no path to a transaction.

1. Kill switch

The trading process refuses to start unless HOOD_MCP_ENABLE_TRADING is exactly 1 and ROBINHOOD_CHAIN_PRIVATE_KEY is a well-formed 32-byte hex key. There is no in-band way for a model to flip it: the check runs at boot, before any transport is connected. 

HOOD_MCP_ENABLE_TRADING=1
ROBINHOOD_CHAIN_PRIVATE_KEY=0x...   # env only, never in a config file you commit

Stopping the process is the whole revocation story: kill it and the key is out of reach.

2. Hard spend caps, in USD

Every mutating call is priced in USD before it is signed and checked against two independent caps. Exceeding either one is a refusal, not a warning, and the ledger is charged only after a broadcast succeeds.

VariableDefaultScope
HOOD_MCP_MAX_SPEND_USDG25One call. A single execute_swap or transfer_usdg above this is rejected outright.
HOOD_MCP_MAX_SESSION_USDG100Cumulative for the process lifetime, held in memory. Restarting resets it, which is deliberate: a restart is a human action.

Valuation uses the same live pricing path the data tools use, so a cap of 25 means 25 dollars of token, not 25 units of whatever the model happened to name.

3. Simulate, then confirm

The first call to a mutating tool never signs. It returns a simulation: the resolved token addresses, the exact amount in and minimum out, the recipient, the USD value, and the caps it was checked against. Only a second call carrying confirm: true with identical arguments broadcasts. 

execute_swap({ tokenIn: "USDG", tokenOut: "WETH", amountIn: "10" })
  -> { simulation: { amountOutMinimum, usdValue, spendRemaining, ... }, confirmRequired: true }

execute_swap({ tokenIn: "USDG", tokenOut: "WETH", amountIn: "10", confirm: true })
  -> { txHash, blockNumber, status, explorer }

This gives the human in the loop a rendered recipient and amount to read before anything moves, which is the only review step that reliably catches a mis-routed tool call.

4. Stock Token eligibility gate

Stock Tokens are tokenized debt securities issued by Robinhood Assets (Jersey) Ltd. They may not be offered, sold, or delivered to US persons, with further limits for Canada, the UK, and Switzerland. The restriction is legal and front-end enforced, not enforced by the contracts, so this server enforces it itself.

  • Reading is never gated. Quotes, portfolios, premiums, and search work for everyone. That is data, not an offer.
  • Acquiring is gated. Any swap whose output is a Stock Token throws unless HOOD_MCP_ACKNOWLEDGE_ELIGIBILITY=1 is set, which is the operator affirming they are eligible.
  • Selling is never gated. Exiting a position you already hold is always allowed.
  • Memecoins are unrestricted. NOXA and The Odyssey tokens are not securities and carry no gate.

This is a config-level affirmation, not a geo-IP check. Setting the variable does not make you eligible; it records that you say you are.

Key handling

  • The key is read from the environment once, at boot, and turned into a viem account. It is never logged, never returned by a tool, and never written to disk by this package.
  • Tool results carry addresses and transaction hashes, never key material.
  • .env* is gitignored in this repo. Client configs that inline a key (Claude Desktop, Cursor) live outside version control by design; prefer exporting the variable in the shell that launches the client.
  • Use a dedicated wallet holding only what you are willing to have an agent spend. The caps above bound the loss per session; the wallet balance bounds it absolutely.

What is actually tested

The guards are covered by tests/trading-guards.test.ts (spend caps, the confirm round trip, the eligibility gate, the kill switch) and the tool schemas by tests/schema.test.ts. Live data tools run against real mainnet in npm run test:live, and npm run test:swap performs a real testnet swap through execute_swap when a funded key is present. 

npm test           # schema + guard tests
npm run test:live  # every data tool against live chain 4663
npm run test:swap  # real testnet 46630 swap, requires a funded key
