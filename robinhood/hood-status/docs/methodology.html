Methodology

A status page is only worth trusting if it publishes its rules. This page documents exactly how hood-status decides what is operational, degraded, or down, and where its blind spots are. The thresholds below are not a paraphrase: the same status-core.js module containing these numbers runs in the probe worker and in this page's direct-probe fallback.

How probing works

A small worker probes the public Robinhood Chain surface every 30 seconds and keeps a rolling 90 days of samples in SQLite. Every probe is a real request against the real endpoint: no synthetic data, no cached green. If the page cannot reach the worker, it flips to direct probe mode and runs the same measurements from your browser (the public RPC, feed, and explorer all allow cross-origin reads), evaluated with the same thresholds. Direct mode has no memory, so uptime bars and incident history pause until the worker is reachable.

No fake green

If a probe cannot run, its component reports unknown, never operational. Days without collected data render gray in the uptime bars, not green. A brand-new worker says so on the page instead of implying 90 days of perfection.

Component rules

ComponentMeasurementDegradedDown
Public RPC eth_blockNumber round trip, 8s timeout median latency over ~5 min > 1500 ms request fails or times out
Block production latest block height, timestamp age, blocks/min head older than 120 s, or < 1 block/min with a > 60 s-old head head older than 300 s
Sequencer feed WebSocket connect, message rate, sequence number vs RPC head silent > 60 s while the chain advanced, or > 50 blocks behind the RPC head not connected
Settlement (L1 view) latest block's l1BlockNumber vs the real Ethereum head ≥ 50 L1 blocks behind (~10 min) ≥ 300 L1 blocks behind (~1 h)
Blockscout explorer GET /api/v2/stats, 10 s timeout request fails never: the explorer is not consensus-critical, so it caps at degraded
Chainlink stock feeds latestRoundData() age on 5 Stock Token feeds (AAPL, TSLA, NVDA, MSFT, AMZN), sampled every 5 min stalest feed > 30 min old during US market hours never: caps at degraded (see limitations)

Gas base fee (current, p50, p95 over the last 128 blocks) is reported as an informational metric only. Base fee moves with organic demand; a spike is not an outage, so it never opens an incident.

Incidents and flap suppression

  • A bad evaluation must persist 3 consecutive probe cycles (~90 s) before an incident opens. A single failed probe never pages anyone.
  • Recovery must persist 4 consecutive cycles (~2 min) before an incident closes. Flapping endpoints stay visibly broken instead of blinking.
  • Severity changes inside an open incident (degraded escalating to down and back) are recorded on the same incident with timestamps.
  • Unknown never opens or closes an incident. If the prober itself breaks mid-incident, the incident stays open rather than being silently resolved.
  • The overall banner is the worst component status. Unknown components are excluded unless everything is unknown.

Why "Settlement (L1 view)"

Robinhood Chain is an Arbitrum Orbit L2 settling to Ethereum. Every L2 block records the parent-chain block the sequencer has ingested (l1BlockNumber). In healthy operation this trails the real Ethereum head by 0 to 2 blocks. If the gap grows, the sequencer has stopped following Ethereum: deposits stall first, then finality. Comparing that view against an independent public Ethereum RPC is a bridge-path heartbeat that needs no privileged infrastructure and cannot be faked by the chain itself.

Honest limitations

  • Market hours, not market calendar: the Chainlink check knows NYSE hours (09:30 to 16:00 ET, DST-correct, weekends closed) but ships no exchange-holiday calendar. On a US market holiday the feeds legitimately idle during "market hours", which can show as degraded. That is why this component caps at degraded and never contributes a "down" banner.
  • Weekend feed staleness is expected: Stock Token feeds go quiet from Friday close to Monday open. The page labels this state instead of alarming on it.
  • One vantage point: probes run from a single region (plus your browser in direct mode). A regional network issue between the worker and the chain can look like a chain issue. Cross-checking with direct probe mode from your own connection is the built-in second opinion.
  • Block production nuance: Arbitrum-lineage chains mint blocks on demand. Robinhood Chain has produced hundreds of blocks per minute continuously since launch, so sustained silence is treated as a stall. If organic activity ever drops to near zero, this rule would need revisiting; the threshold requires both a stale head and near-zero production before degrading.
  • History durability: the worker stores samples in SQLite on its instance disk. On Cloud Run, redeploying or replacing the instance resets history (see the README's data-retention notes). The page says "young worker" instead of hiding it.

Verify it yourself

# the same calls the prober makes, from any terminal:
curl -s -X POST https://rpc.mainnet.chain.robinhood.com \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_blockNumber","params":[]}'

curl -s https://robinhoodchain.blockscout.com/api/v2/stats

# Chainlink AAPL feed, latestRoundData():
curl -s -X POST https://rpc.mainnet.chain.robinhood.com \
  -H 'content-type: application/json' \
  -d '{"jsonrpc":"2.0","id":1,"method":"eth_call","params":[{"to":"0x6B22A786bAa607d76728168703a39Ea9C99f2cD0","data":"0xfeaf968c"},"latest"]}'
