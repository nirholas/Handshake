## What changed in the tree today

- **The `mcp://` interop bug is closed, and it was not what the note said.** The official
  `@x402/mcp` auto-pay client handles `mcp://tool/<name>` resource URLs fine: driven against the
  published stdio server it returned `paymentMade: true` and the server answered
  `transaction_simulation_failed`, the correct result for a deliberately unfunded ephemeral buyer.
  What WAS broken on our side is that the bazaar discovery extension declared
  `transport: "stdio"`, a value the spec does not allow (`VALID_MCP_TRANSPORTS` is
  `streamable-http | sse`), so `validateDiscoveryExtensionSpec` rejected every row and an indexer
  would drop it. The field is optional and a stdio server has no valid value for it, so it is now
  omitted in `mcp-server/src/payments.js`, `packages/ibm-x402-mcp/src/payments.js` and
  `examples/paid-mcp-server/src/payments.js`. Re-driven live: `bazaar spec {"valid":true}`,
  `bazaar schema {"valid":true}`. The client half of that claim is now pinned by a second
  re-runnable check, `node scripts/x402-mcp-url-interop-check.mjs`, which stands an in-memory MCP
  server up with upstream's own `createPaymentWrapper` and drives it with a real signer: it exits 0
  today, and a URL rejection would make it throw before any signing with `paymentMade` false.
- **One genuine upstream defect remains, with a runnable reproduction.**
  `node scripts/x402-bazaar-mcp-url-repro.mjs` shows that `@x402/mcp`'s own
  `createToolResourceUrl` mints `mcp://tool/<name>`, and `@x402/extensions`' bazaar
  `extractDiscoveryInfo` canonicalizes it to `"null/<name>"` because `mcp:` is not a WHATWG
  special scheme and `URL.origin` is the string `"null"`. Two packages from one monorepo disagree
  about a URL neither treats as invalid; every MCP row an indexer keys on it collides on `null`.
  The script exits 1 while the bug is live and 0 once it is fixed. Filing it is a human step (it
  posts to an external tracker).
- **The canonical listing source has a generator again.** `scripts/build-mcp-listing-source.mjs`
  reads every factual field from the manifests and keeps only curated copy in its OVERLAY;
  `npm run audit:mcp-listing` (wired into `npm run gate`) fails when the committed JSON drifts. It
  found the file six servers short and thirty-five versions behind. The untracked leftover copy at
  `_generated/build-mcp-listing-source.mjs` was deleted, so one generator owns the file.
- **`robinhood/hood-mcp` is now audited and publishable.** Adding it to the manifest audit
  surfaced two real defects it had been hiding behind the audit's discovery gap: a missing
  `mcpName` in its `package.json` and its absence from `scripts/publish-mcp-servers.mjs`. Both
  fixed; it also gained the `title` every sibling manifest carries. Note its local manifest is
  `0.1.0` while the registry already serves `0.1.1`, so this repo's copy lags the published
  package by a patch.
- **The staged registry batch was overstating the work by 16 publishes, and the cause was
  pagination.** `build-registry-republish.mjs` read a single `limit=100` page of
  `registry.modelcontextprotocol.io`. That page returns 100 VERSION rows covering only ~44 distinct
  server names and hands back a `nextCursor` of `provenance-mcp:0.1.0`, so every server
  alphabetically at or after that cursor was silently classified NEW. That is why the batch listed
  all 7 hosted remotes as needing a publish when the registry already served them. The loader now
  follows the cursor to exhaustion (160 version rows across 72 names), and the batch went from 20
  commands to a correct **3**. The embedded verification snippet had the same one-page flaw and now
  points at `node scripts/publish-mcp-servers.mjs --dry-run`, which queries per server.
- **The free lane is slow but never hangs, and it has a documented escape hatch.** Six back-to-back
  `forge_free` calls returned **HTTP 200 six times out of six**: one inline at 143s with a real
  2,881,160-byte GLB (`glTF` magic, `/viewer?src=` 200), and five that crossed the server's cutoff
  and correctly returned a structured `pending` result carrying a `jobId`. `STUDIO_FORGE_TIMEOUT_MS`
  is unset in production, so the 180,000 ms default in `api/_mcp-studio/forge-client.js` applies.
  Verified end to end: a 205s call's pending handle passed to the **`check_job`** tool returned the
  finished GLB. Section 6 of the submission package now warns that a client with a 60s default
  timeout (the `@x402/mcp` default) should raise it or expect the pending path. Backend choice
  explains the spread: over 24h `forge_creations` shows `hunyuan3d` averaging 94s to done and
  `trellis_selfhost` 235s.
- **`grade_sim_readiness` was failing `audit:mcp-safety`**, declaring `readOnlyHint: true` over a
  `db-write`. The write is `putGrade()`, a read-through cache fill wrapped in try/catch that returns
  null on failure, so the caller receives the same grade either way. Recorded as a reviewed
  category-1 exemption in `scripts/audit-mcp-safety.mjs` rather than weakening the annotation or the
  gate.
- **`packages/home-mcp/server.json` carried a 131-character description** against the registry's
  100-character maximum, which fails `audit:mcp` and would be rejected at publish. Shortened to 93.
  Its five tools also joined the golden fixture and the public catalog, which is why the tool count
  moved from 306 to 307.
- **The submission package's allowed-link list was wrong in both directions.**
  `https://three-ws-public.r2.dev` is referenced by no handler and returns 500, so it was dropped;
  generated assets are served from `https://three.ws/cdn/...`. `https://solscan.io` is the explorer
  the agent registry and persona wallet tools actually emit (58 references) and was **missing**,
  which would have produced confirm prompts for a reviewer. Added, with `https://explorer.solana.com`.
- **Two shipped tool titles carried an em-dash**, which the house rules ban in UI copy: `persona_say`
  and `persona_identity`. Corrected at source in `api/_mcp3d/tools/studio.js`,
  `api/_mcp-studio/persona-tools.js` and `api/_mcp3d/tools/persona-identity.js`. Production serves
  the old punctuation until the next deploy, and the submission package says so explicitly.
- **`npm run audit:mcp-reviewer` is new** (`scripts/audit-mcp-reviewer-path.mjs`). The connector
  reviewer evidence used to be hand-run curl transcripts that went stale the moment a tool landed;
  it is one command now. It immediately found that the "16/16 paid tools" figure was four tools
  out of date.
